The **Input Box** collects user input and stores it in [User Data](/features/user-data). Settings are grouped into four areas: **Configuration**, **Content**, **Validation**, and **More**.

Some options are Input Box–specific; others are shared with other component types and also appear here.

## Configuration

Basic input behavior and appearance.

<AccordionGroup>
  <Accordion title="User Input">
    Whether users must complete this input before proceeding.

    - Optional (`false`)
    - Required (`true`)

    <Info>
      Shared setting for Input Box, Option Selector, Button, Calendly, File Upload, and PayPal.
    </Info>

    When Required, users cannot continue until they provide a value.
  </Accordion>

  <Accordion title="Height (Multiline)">
    Single-line field or multi-line textarea.

    - Single-line (`false`)
    - Multi-line (`true`)
  </Accordion>

  <Accordion title="Autofocus">
    Focus this input when the page loads.

    - Off (`false`)
    - On (`true`)

    <Warning>
      Use autofocus on only one element per page to avoid accessibility issues.
    </Warning>
  </Accordion>

  <Accordion title="Range Min">
    Minimum value for number, range, date, or month inputs.

    <Info>
      Only when subtype is `"range"`, `"date"`, or `"month"`.
    </Info>
  </Accordion>

  <Accordion title="Range Max">
    Maximum value for number, range, date, or month inputs.

    <Info>
      Only when subtype is `"range"`, `"date"`, or `"month"`.
    </Info>
  </Accordion>

  <Accordion title="Range Step">
    Step increment for number and range inputs (for example, `10` → 0, 10, 20…).

    <Info>
      Only when subtype is `"range"`.
    </Info>
  </Accordion>
</AccordionGroup>

<AccordionGroup>

    <Info>
      Only when subtype is `"switch"`.
    </Info>
  </Accordion>

  <Accordion title="Off label">

    <Info>

</AccordionGroup>

## Validation

Rules and messages that keep input data valid.

### Enable validation

<AccordionGroup>
  <Accordion title="Validate Value">
    Turn validation on or off.

    - Disabled (`false`)
    - Enabled (`true`)

    Other validation settings require this to be enabled.
  </Accordion>

  <Accordion title="Formula">
    Validation formula for the input value.

    <Info>
      Only when **Validate Value** is enabled.
    </Info>

    | Option | Value | Available for |
    | --- | --- | --- |
    | None | `"none"` | All subtypes |
    | Full Name | `"full_name"` | Text only |
    | Email | `"email_address"` | Email only |
    | Business Email | `"business_email"` | Email only |
    | Phone Number (US) | `"phone_number_us"` | Phone only |
    | Number Range | `"number_range"` | Number only |
    | Custom formula | `"custom"` | All subtypes (opens JS editor) |

    <Tip>
      Custom formulas return `true` for valid values and `false` for invalid ones. They receive the input value, and optionally full User Data:

      ```javascript
      function validate(value) {
        return value.length >= 5;
      }

      function validate(value, userData) {
        return userData.country === "US" ? /^\d{5}$/.test(value) : true;
      }
      ```
    </Tip>
  </Accordion>
</AccordionGroup>

### When validation runs

<AccordionGroup>
  <Accordion title="Validate on blur">
    Run validation when the field loses focus.

    <Info>
      Only when **Validate Value** is enabled.
    </Info>
  </Accordion>

  <Accordion title="Trim whitespace on blur">
    Remove leading and trailing spaces on blur.

    <Info>
      Only when **Validate Value** is enabled.
    </Info>
  </Accordion>

  <Accordion title="Format email on blur">
    Normalize email casing on blur (for example, `JOHN@EXAMPLE.COM` → `john@example.com`).

    <Info>
      Only when **Validate Value** is enabled and subtype is `"email"` or `"text"`.
    </Info>
  </Accordion>
</AccordionGroup>

### Messages and limits

<AccordionGroup>
  <Accordion title="Empty message">
    Error shown when a required field is empty.

    <Info>
      Only when **Validate Value** is enabled and the field is required.
    </Info>
  </Accordion>

  <Accordion title="Invalid message">
    Error shown when validation fails.

    <Info>
      Only when **Validate Value** is enabled.
    </Info>
  </Accordion>

  <Accordion title="Max length of input">
    Maximum characters allowed.

    <Info>
      Only when subtype is `"text"` or `"password"`.
    </Info>
  </Accordion>
</AccordionGroup>

### Number range validation

These apply when **Validate Value** is on, **Formula** is `"number_range"`, and subtype is `"number"`. They differ from Configuration **Range Min/Max**, which constrain the control itself.

<AccordionGroup>
  <Accordion title="Range min (Validation)">
    Reject numbers below this minimum.
  </Accordion>

  <Accordion title="Range max (Validation)">
    Reject numbers above this maximum.
  </Accordion>

  <Accordion title="Allow Integers only">
    Allow whole numbers only (reject decimals).
  </Accordion>
</AccordionGroup>

## More settings

Advanced options.

<AccordionGroup>
  <Accordion title="Repeat Component">
    Repeat this component for each item in a User Data array.

    - Off (`"hide"`)
    - On (`"show"`)

    When on, choose a **Repeater key** (array in User Data; keys starting with `split_` are excluded).

    <Info>
      Shared setting for all components except Page and Embeddable.
    </Info>
  </Accordion>

  <Accordion title="Ignore in QA tests">
    Skip this element in Embeddables automated QA tests.

    <Info>
      Shared setting for Button and Input Box.
    </Info>
  </Accordion>

  <Accordion title="Input Debounce Time">
    Delay (ms) before User Data updates after typing. Reduces updates while the user is still typing.

    <Info>
      Not available when subtype is `"switch"` or `"checkbox"`.
    </Info>

    <Tip>
      Useful when Computed Fields or Actions depend on this input.
    </Tip>
  </Accordion>

  <Accordion title="Element ID">
    Custom HTML element ID for CSS or JavaScript targeting.

    <Info>
      Shared setting for all components except Page.
    </Info>
  </Accordion>
</AccordionGroup>
