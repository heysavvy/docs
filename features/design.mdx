The Design sidebar in the Builder styles your Embeddables with a CSS-based system. You apply styles to components, pages, or the whole Embeddable using **tags**, **element selectors**, **breakpoints**, and **states**.

## How styling works

When you change styles in the Design sidebar, Embeddables generates CSS rules that target elements through a **selector constructor**. Each selector is built from up to five parts:

| Part | What it controls |
| --- | --- |
| **Styling tag** | Which components the styles apply to |
| **Element** | Which part of the component is styled |
| **Breakpoint** | Which screen sizes the styles apply at |
| **State** | Interaction state (hover, focus, and so on) |
| **Scope** | Where the styles apply (entire Embeddable, one page, or pages with a tag) |

The sections below cover each part in more detail.

## Styling workflow

Use this order when styling a component or page:

1. Select the component or page.
2. Add or select a styling tag.
3. Choose the element to style.
4. Start on the **Desktop** breakpoint, then add tablet or mobile overrides.
5. Apply styles in the style panels.
6. Preview at different screen sizes with the breakpoint toggle in the Builder.

## Styling tags

Tags are the foundation of styling in Embeddables. Use them to style many components at once and to reuse style patterns across your Embeddable.

### Add a tag

<Steps>
  <Step title="Select a component or page">
    Click the component or page in the Layers sidebar or the preview pane.
  </Step>
  <Step title="Open the Design sidebar">
    Click the **Design** tab in the left sidebar.
  </Step>
  <Step title="Add a styling tag">
    Open the **Add a tag** dropdown, select an existing tag or type a new name, then press Enter or click to add it.
  </Step>
</Steps>

### Manage tags

After a tag is on a component:

- All tags for the selected component appear in the Design sidebar.
- Click a tag to select it and view or edit its styles.
- You can add multiple tags to one component.
- Remove a tag with the **X** next to its name.

### Conditional tags

Apply tags based on [User Data](/features/user-data) and [Conditions](/features/conditions) so styling can change with user input or experiment variants.

1. In the Design sidebar, open the **Styling tag** dropdown.
2. Click **Convert to conditional tag** (the tag moves into a **Conditional tags** section).
3. Click **Conditions** or **Experiment conditions** on the tag.
4. In the popup, set when the tag should apply.

### Tag naming and structure

Use a clear tag structure so styles stay reusable and easy to maintain.

#### Naming

- Use descriptive names that state the purpose (for example, `primary_button`, `section_header`).
- Use `snake_case` (lowercase with underscores).

#### Primary tags

Give each component **one primary tag** for its default look (for example, `standard_button` or `pricing_card`). Put the full base styles on that tag, except styles that come from secondary tags or one-off overrides.

#### Secondary tags

Use **secondary tags** to specialize a primary tag without copying most of its styles. Secondary tags can override a few primary styles, but should not replace most of them.

Examples:

- `standard_button` + `primary_button` (color change).
- `standard_option_buttons` + `option_buttons_2_cols` (two-column layout, spacing, centered text).

#### Spacing and one-off styles

- For a single style such as margin or padding, prefer a Tailwind-style tag in `snake_case` (for example, `mt_10`, `mb_0`, `pt_8`) instead of a new secondary tag.
- If a spacing value is useful on every instance, put it on the **primary** tag.
- For spacing between components, prefer `gap` on the parent container when possible.

- **Whole thing** — the full component container.

## Breakpoints

Breakpoints make layouts responsive. Embeddables ships with defaults and supports custom breakpoints.

### Default breakpoints

- **Desktop** — all screen sizes (no max-width).
- **Tablet** — screens 720px and below.
- **Mobile** — screens 520px and below.

### How breakpoints cascade

Breakpoints use CSS `max-width` media queries:

1. Styles for a breakpoint are wrapped in a media query for that max-width.
2. Styles cascade from larger to smaller breakpoints.
3. Desktop styles apply everywhere unless overridden.
4. Tablet overrides desktop at 720px and below.
5. Mobile overrides desktop and tablet at 520px and below.

In generated CSS, breakpoints are ordered from highest to lowest max-width so smaller breakpoints correctly override larger ones.

### Use breakpoints in the Builder

1. Select a component or page.
2. Open the Design sidebar.
3. Choose a breakpoint from the **On** dropdown.
4. Apply styles — they affect screens at or below that breakpoint's max-width.

<Tip>
  Style desktop first, then add tablet and mobile overrides. This is usually faster than rebuilding styles at every breakpoint.
</Tip>

### Custom breakpoints

Custom breakpoints target sizes beyond the defaults. They are configured in the Embeddable JSON.

<Note>
  Contact Embeddables support if you need help setting up custom breakpoints.
</Note>

Add entries to the `breakpoints` array in your Embeddable configuration:

```json
{
  "breakpoints": [
    {
      "name": "large_tablet",
      "max_width": 1024
    },
    {
      "name": "small_mobile",
      "max_width": 375
    }
  ]
}
```

Each breakpoint needs:

- **name** — a descriptive `snake_case` name.
- **max_width** — maximum screen width in pixels where the styles apply.

## States and scope

Use these advanced selector options when you need more precise targeting.

### State selectors

Style components based on interaction:

- **Always** — default state (no state selector).
- **Hover** — pointer is over the element.
- **Focus** — element has focus.
- **Active** — element is being clicked.
- **Disabled** — element is disabled.

<Note>
  Hover styles are wrapped in `@media (hover: hover)` so they do not misbehave on touch devices.
</Note>

### Scope selectors

Control where tag styles apply:

- **Entire Embeddable** — everywhere the tag is used.
- **This page only** — only on the current page.
- **Pages with tag** — only on pages that have a specific tag (for example, all buttons on interstitial pages).

### Target options by key

For Option Selector and Advanced Dropdown components, you can style a specific option by its key when one option needs different styles from the others.

### Custom CSS selectors

Advanced users can write custom CSS selectors directly.

<Note>
  Custom CSS selectors are an advanced feature. Contact Embeddables support for guidance.
</Note>

## Additional tips

- Reuse tags for common patterns instead of creating many one-off tags.
- Prefer simpler selectors when you can.
- On mobile, keep interactive targets at least 44×44px.
- Use the Builder breakpoint toggle to preview desktop, tablet, and mobile before publishing.
