The **Embeddables CMS** lets you manage dynamic content outside the Builder — for example Stripe prices or programmatic SEM page content — and use that data across Embeddables.

## Benefits

- Update content without changing or deploying Embeddable code.
- Edit data in a simple table UI.
- Keep an audit trail of changes.
- Reflect CMS updates in Embeddables as soon as the CMS version is live.
- Let non-technical teammates manage content.

## Create and manage tables

1. Open **CMS** in the Embeddables Web App.
2. Click **Edit Tables**.
3. Click **+ Add Table** and start from a template or a blank table.
4. Configure columns (name, key, and type).

Then:

- Add rows with **+ Add Row**.
- Edit cells by clicking them.
- Note each table's ID — you use it when connecting the table to an Embeddable.

### Available templates

- **Blank table** — start from scratch.
- **Prices** — product or service pricing.
- **URLs & links** — routing and redirects.
- **FAQs** — frequently asked questions.
- **Programmatic pages** — dynamic page content.
- **Coupons** — promo codes and discounts.

Each template includes a recommended schema you can customize.

## Connect a table to an Embeddable

<Steps>
  <Step title="Add a content source">
    In the Builder, deselect pages and components (press Escape), open Embeddable **Options**, scroll to **CMS**, and click **+ Add Content Source**.
  </Step>
  <Step title="Choose a User Data key">
    Enter the key under which CMS data should be stored in User Data.
  </Step>
  <Step title="Select a table">
    Pick the table to connect. If none appear, save the table as a version in the CMS first.
  </Step>
  <Step title="Choose which records to fetch">
    Under **Which records should get shown?**:

    - **Show all records** — fetch all rows (or the first row if **Multiple Records** is unchecked).
    - **Records that match a URL pattern** — fetch rows that match the URL. Set **Controller Key** to the column used for matching.

    Check **Multiple Records** when you need a list (for example FAQs or prices).
  </Step>
  <Step title="Register the key and use the data">
    Add the User Data key to **Registered Keys** in Embeddable Options. Reference the data like any other User Data property.
  </Step>
</Steps>

<Warning>
  On preview links, add <code>savvy_test=false</code> so CMS data loads as expected.
</Warning>

## CMS version control

The CMS has its own version control (save, switch, Staging, Production) in the top-right when editing tables.

Preview an Embeddable against a CMS version with `savvy_cms`:

| Goal | Param |
| --- | --- |
| Specific version | `savvy_cms=123` |
| Latest | `savvy_cms=latest` |
| Staging | `savvy_cms=staging` |

## Example use cases

### Stripe prices

Manage pricing in CMS so you can update prices without Builder releases.

| Column name | Column key | Purpose |
| --- | --- | --- |
| Plan name | `plan_name` | Identifies the plan |
| Stripe Price ID | `stripe_price_id` | Links to Stripe |
| Price amount | `price_amount` | Display price |
| Size | `size` | Plan size |
| Discount type | `discount` | Discount flag |

### Programmatic SEM pages

Drive templated page content from URL patterns so one Embeddable can power many landing pages.

| Column name | Column key | Purpose |
| --- | --- | --- |
| Page URL | `url_slug` | URL path for the content |
| Title | `title` | Page title |
| Description | `description` | Meta description |
| Content | `content` | Main body |
| Image URL | `image_url` | Featured image |

## Tips

- Design the table schema before you create it.
- Use clear column names and `snake_case` keys.
- Preview with `savvy_cms=latest` before pushing CMS changes to Production.
