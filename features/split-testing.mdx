## How Experiments work

When an experiment launches, each user is randomly assigned a variant. That assignment is stored in User Data under the experiment key.

Example: experiment key `split_hero_title_length` with variants `control_no_change` and `variant_longer_title` might set:

```
split_hero_title_length: 'variant_longer_title'
```

You then add **Experiment Conditions** on pages or components so each version of the content shows only for its variant (for example, clone a title, change the copy, and condition each clone on its variant).

## Set up an Experiment

<Steps>
  <Step title="Create the experiment">
    - Open the **Logic** tab (top-left).
    - Open the **Experiments** tab.
    - Click **+ Add new experiment**.
  </Step>
  <Step title="Set keys and traffic split">
    - Choose an experiment key. Keys always start with `split_` (for example, `split_hero_title_length`).
    - Choose keys for each variant. Prefer `control_...` for the control and `variant_...` for treatments.
    - Set the percentage of traffic for each variant.
  </Step>
  <Step title="Change content per variant">
    - Select the page or component to vary.
    - Clone it and edit the clone for the first treatment.
    - In **Options**, add an Experiment Condition for that experiment key and variant.

      <Tip>
        The component may disappear in the Builder if you are not viewing that variant.
      </Tip>

    - Add an Experiment Condition on the control version as well.

      <Tip>
        Control conditions usually include a `no_value` option so the control shows by default before assignment.
      </Tip>

    - Repeat for any other variants.
  </Step>
  <Step title="Preview, test, and launch">
    - In the Experiments sidebar, use the Preview (<Icon icon="eye" iconType="solid" />) controls next to each variant.
    - Save your changes.
    - Test with [`savvy_flow_version=latest`](/features/url-params). To force a variant, add the experiment key and value as a URL param.
    - Once assigned, a user stays in that variant until local storage is cleared or they switch browsers.
    - Launch by pushing the version to Staging, then Production.
  </Step>
</Steps>

## Pause an Experiment

<Steps>
  <Step title="Pause">
    Select the experiment and click <Icon icon="pause" iconType="solid" /> **Pause** in the right-hand sidebar.
  </Step>
  <Step title="Choose a default variant">
    Select which variant to show while the experiment is paused.
  </Step>
</Steps>

Pausing moves the `no_value` value onto the conditions for the chosen variant. New users no longer get experiment keys in User Data and see that default. Existing users keep their assigned variants.

## End an Experiment

<Warning>
  Ending an experiment is permanent. To undo it, switch to a previous version where the experiment was still active and save from that version.
</Warning>

<Steps>
  <Step title="End">
    Select the experiment and click <Icon icon="stop" iconType="solid" /> **End** in the right-hand sidebar.
  </Step>
  <Step title="Choose the winner">
    Select the winning variant. Pages and components for the other variants are deleted, and Experiment Conditions for this experiment are removed.
  </Step>
</Steps>
