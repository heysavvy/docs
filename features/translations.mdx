**Translations** let you offer an Embeddable in multiple languages. You configure languages at the Embeddable level, edit content per language in the Builder, and show end users the language that matches their choice (via User Data or URL params).

## How translations work

Every Embeddable has a **default language** (English). After you add more languages:

- A **content language** dropdown appears in the Builder top bar (editing mode).
- The dropdown controls which language you are editing; new content is saved for that language.
- Translatable fields (text, labels, placeholders, button labels, and so on) are stored per language.

Edit either in the **Options** panel (**Content** section) or by clicking text directly in the preview. Both respect the selected content language.

## Manage languages

Languages are configured on the Embeddable, not on individual pages or components.

<Steps>
  <Step title="Open Embeddable Options">
    Deselect any page or component (click empty space or press Escape) so the Options panel shows Embeddable-level settings.
  </Step>
  <Step title="Open Translations">
    In the left sidebar, open **Options**, then expand **Translations**.
  </Step>
  <Step title="Add a language">
    Click **Add** and set:

    - **Key** — short code (for example, `es`, `en_us`, `fr`). Follow [naming keys](/guides/naming-keys).
    - **Name** — display name in the Builder (for example, Español).

    The language appears below the default language.
  </Step>
</Steps>

- **Default language** — English cannot be removed; it has no Edit/Delete action.
- **Edit** — change the **Name** only; the **Key** is fixed after creation.
- **Delete** — removes the language; stored content for it is no longer shown to end users.

## Edit translated content

You need at least two languages configured.

### Switch content language

1. In editing mode, open the content language dropdown in the top bar (next to the breakpoint toggle).
2. Select the language to edit.
3. Further edits apply to that language until you switch again.

The selection is remembered for your Builder session.

### Edit in the Options panel

1. Select the content language.
2. Select a component or page.
3. In **Options** → **Content**, edit translatable fields for the active language.

Supported components include Plain Text, Rich Text, Rich Text Markdown, Custom HTML, Input Box, Option Selector, Custom Button, File Upload, Stripe Checkout, and Media Image.

### Edit in the preview

1. Select the content language.
2. Click the text in the preview and type your changes.
3. Changes save for the active language.

### Empty fields and fallback

If a translation is empty, the default language (English) is shown in the Builder and on the published Embeddable.

When editing in place:

- Switching to a language with no translation yet shows the default text. Editing that text starts the translation for that language.
- Leaving without changes (or reverting to the original before blur) keeps the translation empty, so the default remains.
- Any edit that leaves the field different from the original saves the translation.
- Clearing the field and deselecting empties the translation again, so the default is shown.

## End-user language

At runtime, the language comes from `embeddable_language` in [User Data](/features/user-data) when present. You can:

- Set it with `setUserData` (or equivalent), for example `embeddable_language: 'es'`.
- Pass it via a [URL param](/features/url-params) if the key is in your allowed URL keys.

If the value is missing or does not match a configured language, the default language loads.

### Let users choose a language

A common pattern is an **Option Selector** dropdown:

1. Add an Option Selector and place it on the page.
2. Set its **key** to `embeddable_language`.
3. Add one option per language; set each option **key** to the language key (`en`, `es`, `fr`, …) and use the labels for display names.

Selecting an option updates User Data and switches the visible language.
