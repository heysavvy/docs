**Computed Fields** calculate new values from [User Data](/features/user-data). They take inputs from the User Data object, return an output, and write that output back into User Data under the field's key.

You can use the result in text components, [conditions](/features/conditions), other Computed Fields, and more. Computed Fields also have access to helper functions (such as `setUserData` and `triggerAction`) and context about what triggered the run.

They run **client-side** in the main window, so they can use browser APIs like `window.location`, `document`, and `localStorage`.

## Create a Computed Field

<Steps>
  <Step title="Add the field">
    - Open the **Logic** sidebar and go to the **Computed Fields** tab.
    - Click **+ Add New Computed Field**.
    - Set a key for the output in User Data (for example, `full_name`).
    - Click **Add**.
  </Step>
  <Step title="Write the code">
    - Define a function named `result()`.
    - Put your JavaScript inside `result()`.
    - The first argument is User Data; the other arguments are described in [Custom code](/guides/custom-code).
  </Step>
</Steps>

## Configuration options

### Storage

Controls where the result is persisted:

- **Save to User Data** (default) — saved to User Data and persisted in cookies or localStorage.
- **Do not save** — calculated for the session but not persisted to storage.
- **Save to cloud only** — saved to the Embeddables database, not stored locally.

### Inputs and triggers

These options control which data the field receives and when it recalculates.

<AccordionGroup>
  <Accordion title="Inputs">
    User Data keys the field depends on. When those keys change, their values are available on `userData`.

    ```js
    function result(userData) {
      return `${userData.first_name} ${userData.last_name}`;
    }
    ```
  </Accordion>

  <Accordion title="Triggers">
    Keys that cause the field to re-run. Use this when the field should recalculate only when specific values change, even if it reads other inputs.

    Example: a total that reads many keys but only recalculates when `recalculate_total` changes.
  </Accordion>

  <Accordion title="Include and watch full User Data">
    - Receives the entire User Data object (excluding its own key, to avoid circular references).
    - Re-runs whenever **any** User Data value changes.

    ```js
    function result(userData) {
      return Object.keys(userData).length;
    }
    ```
  </Accordion>

  <Accordion title="Include, but do not watch full User Data">
    - Receives the entire User Data object (excluding its own key).
    - Re-runs only when keys in **Inputs** or **Triggers** change.

    Useful when you need broad read access but controlled recalculation.
  </Accordion>
</AccordionGroup>

### Async behavior

<AccordionGroup>
  <Accordion title="Async">
    Allows `await` and promises inside the function.

    ```js
    async function result(userData, helperFunctions) {
      const response = await fetch("https://api.example.com/data");
      const data = await response.json();
      return data.value;
    }
    ```

    <Note>
      Sync fields run first for faster updates; async fields run afterward.
    </Note>
  </Accordion>

  <Accordion title="Wait before updating [ms]">
    Available when **Async** is enabled. Debounces recalculation so rapid input changes (for example, typing) do not trigger too many updates. A common value for API calls is `500`.
  </Accordion>

  <Accordion title="Include loading state">
    While an async computation runs, the field key is set to `"_loading"` so you can show a loading state in the UI.

    ```js
    async function result(userData) {
      const response = await fetch("https://api.example.com/data");
      const data = await response.json();
      return data.value;
    }

    // if (userData.my_field === "_loading") { show spinner }
    ```
  </Accordion>
</AccordionGroup>

### Styling from a computed value

**Set value as class on flow** adds a CSS class to the flow container in the format `field-value-{key}-{value}`.

If the key is `user_type` and the value is `premium`, the class is `field-value-user_type-premium`:

```css
.field-value-user_type-premium .pricing-section {
  background-color: gold;
}
```

## Examples

### Full name

```js
function result(userData) {
  return `${userData.first_name} ${userData.last_name}`;
}
```

### BMI

Assumes weight in kilograms and height in centimeters:

```js
function result(userData) {
  const weight = userData.weight;
  const height = userData.height;
  return weight / (height * height);
}
```

### Over 18 from a single date

Assumes `date_of_birth` is a `YYYY-MM-DD` string:

```js
function result(userData) {
  const dob = userData.date_of_birth;
  const eighteenYearsAgo = new Date();
  eighteenYearsAgo.setFullYear(eighteenYearsAgo.getFullYear() - 18);
  return new Date(dob) < eighteenYearsAgo;
}
```

### Over 18 from day, month, and year dropdowns

```js
function result(userData) {
  const day = userData.dob_day;
  const month = userData.dob_month;
  const year = userData.dob_year;
  const dob = new Date(year, month - 1, day);

  const eighteenYearsAgo = new Date();
  eighteenYearsAgo.setFullYear(eighteenYearsAgo.getFullYear() - 18);
  return dob < eighteenYearsAgo;
}
```
