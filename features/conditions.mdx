**Conditions** show or hide a page or component based on a property in [User Data](/features/user-data).

You define which values are acceptable for a key. If the User Data property matches, the page or component is shown; otherwise it is hidden.

Think of a condition as an equation: **key** + **operator** + **value**.

For example, to show a warning for users under 18, the condition is effectively `age_range = 'under_18'`:

- **Key** — `age_range`
- **Operator** — `Is or includes`
- **Value** — `under_18`

## Add a condition

<Steps>
  <Step title="Open page or component Options">
    - Select the page or component in the Layers sidebar or preview pane.
    - Make sure you are on the **Content** tab at the top-left.
    - Open **Options** in the right-hand sidebar.
  </Step>
  <Step title="Configure the condition">
    - Click **+ Add condition**.
    - Choose the User Data **key** that should control visibility.
    - Choose an **operator** (usually `Is or includes`).
    - Choose the **value** that should show the page or component.
  </Step>
</Steps>

## Operators

### Match

<AccordionGroup>
  <Accordion title="Is or includes (==)">
    Checks whether the User Data value matches any of the specified values.

    For single values:

    - Returns true if the value exactly matches any specified value.
    - Returns true if `_no_value` is specified and the value is undefined or null.
    - Returns false otherwise.

    For arrays:

    - Returns true if any specified value is included in the array.
    - Returns true if `_no_value` is specified and any array item is undefined or null.
    - Returns false otherwise.
  </Accordion>

  <Accordion title="Is not or excludes (!=)">
    Checks whether the User Data value does **not** match any of the specified values.

    For single values:

    - Returns true if the value does not match any specified value.
    - Returns true if `_no_value` is specified and the value exists.
    - Returns false otherwise.

    For arrays:

    - Returns true if none of the specified values are in the array.
    - Returns true if `_no_value` is specified and all array items exist.
    - Returns false otherwise.
  </Accordion>
</AccordionGroup>

<Tip>
  For arrays, **Is or includes** matches if **any** listed value is present. **Is not or excludes** matches only if **none** of the listed values are present.
</Tip>

### Existence

<AccordionGroup>
  <Accordion title="Exists">
    Checks whether the value exists (not undefined or null).

    - Single values: true if defined and not null.
    - Arrays: true if the array contains any defined, non-null values.
  </Accordion>

  <Accordion title="Does not exist (!exists)">
    Checks whether the value does not exist (undefined or null).

    - Single values: true if undefined or null.
    - Arrays: true if the array is empty or contains only undefined or null values.
  </Accordion>
</AccordionGroup>

### Boolean

These operators compare against the special values `_true` and `_false`.

<AccordionGroup>
  <Accordion title="Is true (is-true)">
    Returns true only if the value is strictly equal to `_true`.
  </Accordion>
  <Accordion title="Is false (is-false)">
    Returns true only if the value is strictly equal to `_false`.
  </Accordion>
  <Accordion title="Is not true (is-not-true)">
    Returns true for any value that is not strictly equal to `_true`.
  </Accordion>
  <Accordion title="Is not false (is-not-false)">
    Returns true for any value that is not strictly equal to `_false`.
  </Accordion>
</AccordionGroup>

### Empty

<AccordionGroup>
  <Accordion title="Is empty (is-empty)">
    Returns true if the value is:

    - undefined or null
    - an empty array
    - an empty string, or a string with only whitespace
  </Accordion>
  <Accordion title="Is not empty (is-not-empty)">
    Returns true if the value is:

    - defined and not null
    - a non-empty array
    - a string with at least one non-whitespace character
  </Accordion>
</AccordionGroup>

## Special values

In conditions, `_true`, `_false`, and `_no_value` are converted to the appropriate types when evaluated (for example, `_true` becomes the boolean `true`).
